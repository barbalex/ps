# Implement Option B + C: owner-configurable tile layers feeding the background chooser

Options B and C from `tile-layers-proposal.md`: a dedicated `tile_layers` table, and an `is_background` flag that lists project tile layers in the drawer's "Hintergrundkarte" chooser next to OSM/Positron/Dark Matter.

## 1. SQL (edit `backend/db/init/` only, then `npm run sync-sql`)
- **04_createTables.sql**: new `tile_layers` table (`tile_layer_id`, `project_id` FK, `label`, `url_template`, `subdomains jsonb`, `max_native_zoom`, `attribution`, `is_background boolean DEFAULT FALSE`, audit columns) + indexes + comments; `layer_presentations` gains `tile_layer_id` FK (`ON DELETE CASCADE`) + index.
- **05_createHistoryTables.sql**: `tile_layers_history` + versioning trigger, mirroring `wms_layers` (which is versioned).
- **07_triggers.sql**: `layer_presentations_set_project_id_trigger` gets a `tile_layers` branch.
- **12_writePermissionTriggers.sql**: `enforce_project_write` trigger on `tile_layers` (same policy as wms_layers: writer or higher).
- 06 needs nothing (generic updated_at trigger).

## 2. Schema into dev db + prove rebuild works
- Apply the identical delta to the running dev db via `docker exec ps_db psql` (keeps your data).
- Verify a from-scratch rebuild works **without touching your data**: create a throwaway `ps_init_check` database in the dev container, run `backend/db/init/*.sql` in order against it, compare schema of the touched tables + triggers against the dev db, drop it.

## 3. Models + sync
- `npm run models:generate` (dev db now has the table) → `src/models/public/TileLayers.ts`, `LayerPresentations.ts` gains `tile_layer_id`.
- `backend/auth/shapeDefinitions.mjs`: add `tile_layers` shape (`where: project_id IN (...)`), add `'tile_layer_id'` to the `layer_presentations` columns list (it's explicit). `npm run sync-sql` mirrors to backend-dev + src/modules; restart the auth container so it serves the new shape.

## 4. Client modules
- `createRows.ts`: `createTileLayer({ projectId })` — inserts the tile layer **and** its layer_presentation upfront (backgrounds must render for viewers without write access, so the presentation exists from the start; `active` flag stays irrelevant for backgrounds); extend `createLayerPresentation` with a `tileLayerId` branch.

## 5. Renderer
- New `TilesLayer.tsx` (plain `TileLayer` from `url_template`, `subdomains`, `max_native_zoom`, `attribution`, presentation opacity/grayscale/zoom bounds).
- `Layer.tsx`: tile branch after the pseudo-background lookup — query `tile_layers` via `layer_presentation_id`; `is_background` rows render whenever they're in the render list (same semantics as the pseudo backgrounds — visibility is list membership, no db flag needed); non-background rows use the standard flag/override check in a `Pane`.

## 6. Drawer: new "Tiles" section (after WMS)
- `Layers/Tile/index.tsx` + row + form, mirroring the WMS section: add button (`createTileLayer` → accordion opens), rows list all tile layers, config form (label, url template, subdomains, max zoom, attribution, is_background switch), delete menu, `LayerPresentationForm` under Overall Display (plus its `tile_layer_id` tweak for transparent/grayscale switches). Activation toggle only on non-background rows (`activateLayer`/`deactivateLayer` on the existing presentation).

## 7. Active section
- Third live query in `Actives/index.tsx` (`ActiveTileLayerRow`), merged into the sort; only non-background tile layers appear; `Content.tsx` tile branch (label, config tab, delete). The atom-sync effect's removal guard keeps tile-background presentation ids alive (queried live, so deleted layers drop out of the keep-set).

## 8. Hintergrundkarte section (Option C)
- Lists project tile layers with `is_background = true` alongside the three pseudo options (labels from the tile layer). Swap logic generalized: the current background is whichever pseudo id **or** tile-background presentation id sits in the render list; picking replaces it (or appends if none). Pure view-state — no writes, works for read-only users.

UI-add flow verified manually in the browser rather than e2e (the equivalent WMS UI-add test is the known-flaky one on main).
- `url-layers.spec.ts`: self-healing psql that inserts missing presentations for places_1/checks_1, so a from-scratch rebuild doesn't break it.
