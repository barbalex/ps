# Project-level chart templates (`charts.for_subprojects`)

## Concept

A chart with `project_id` set, `subproject_id` NULL and the new column `for_subprojects = TRUE` is a **template**: it appears in every subproject's Charts section and in subproject reports, always computed against the subproject it is viewed in (the display component already takes `subprojectId` from the route, so `buildData` needs no changes). Project reports explicitly **exclude** templates — they describe subprojects, not the project.

The three seeded Aldrovanda charts become templates (available for all three Arten), and a new project-level Charts section (mirroring the WMS Layers pattern) manages them.

## 1. Schema

- `backend/db/init/04_createTables.sql`: add `for_subprojects boolean NOT NULL DEFAULT FALSE` to `charts` + comment; then `npm run sync-sql` (propagates to `src/sql/createTables.sql` and backend-dev).
- Dev DB: `ALTER TABLE charts ADD COLUMN IF NOT EXISTS for_subprojects boolean NOT NULL DEFAULT FALSE;`
- `SqlInitializer` existing-db healing: the same ALTER for `charts` **and** `charts_history` — the history table is created via `LIKE charts`, and the versioning trigger writes all columns, so a missing column would break chart updates on already-provisioned browsers.
- `src/models/public/Charts.ts` (+ Initializer/Mutator): add the field.
- `src/modules/startSyncing.ts`: add `'for_subprojects'` to the charts shape's explicit `columns` list (otherwise it never syncs).

## 2. Templates visible per subproject (tree + list)

- `useChartsNavData`: in the subproject context, extend all three WHERE clauses to `(charts.subproject_id = $sub OR (charts.for_subprojects AND charts.project_id = $project AND charts.subproject_id IS NULL))`; relax the Props type (subprojectId/placeId optional). Place-level contexts stay unchanged. The subproject Charts list uses the same hook → inherits the change.
- `Tree/Chart.tsx` (ChartNode): hide the "Diagramm" leaf when no subprojectId is in scope (no data context at project level); keep Einstellungen + Chart Subjects.
- Mount `ChartsNode` with only `projectId` in `Tree/Project/index.tsx`, gated by the existing `project.charts` flag.

## 3. Project-level routes + creation

- New route tree `/data/projects/$projectId_/charts/…` mirroring the subproject one: `route.tsx` (navDataFetcher `useChartsNavData`), `index.tsx` (existing `Charts` list — already falls back to `{projectId}`), `filter.tsx`, `$chartId_/{route,index,settings,histories/$chartHistoryId,subjects/…}`. **No** `chart.tsx` route.
- `createRows.createChart`: set `for_subprojects = TRUE` when created with only `projectId`; include the column in the INSERT + operation draft.
- `chart/Header.tsx` (+ `HistoryCompare` `from` constants): build the base path for both project-level and subproject-level chart URLs.
- `chartSubject/Field.tsx` (DataKeysField): when no `subprojectId` is in the route, query the distinct `data` jsonb keys across **all subprojects of the project**, so template subjects can pick fields like `status`.

## 4. Settings form

- `chart/Form.tsx`: SwitchField for `for_subprojects`, shown when the chart is project-level (`project_id` set, `subproject_id` NULL). New i18n ids in en/fr/it; add to `historyCompareConfig.preferredOrder`.

## 5. Reports

- `subprojectReport/Print.tsx` and `projectReport/SubprojectReportsSection.tsx` charts subqueries: include templates (`c.subproject_id = sr.subproject_id OR (c.for_subprojects AND c.subproject_id IS NULL AND c.project_id = <project of sr>)`).
- `subprojectReportDesign/Form.tsx`: restrict the project-level part of the charts subquery to templates.
- `projectReport/Print.tsx`: exclude templates (`AND NOT c.for_subprojects`).

## 6. Seed, dev DB, e2e

- `11c_seedApfloraCharts.sql`: the three charts become templates (project_id set, subproject_id NULL, `for_subprojects` TRUE, same UUIDs); verification block adjusted.
- Dev DB: UPDATE the three existing rows accordingly (inside `SET LOCAL electric.syncing`).
- `e2e/charts.spec.ts`: provisioning updated; assert the template renders under Aldrovanda as today **and** appears in the Pulsatilla charts list (data-less there — roles only exist for Aldrovanda — so assert presence, not legend).

## 7. Verification

`tsc`, `vitest run`, i18n punctuation check, `sync-sql:check`; fresh-database simulation (scratch DB, full init chain, assert the three templates); Playwright run of the charts spec plus a manual pass over the new project-level section (create/edit a template, check it appears under each Art).

Permissions need no changes: charts go through the multi-parent write trigger and `checkMultiParent` (project_id → project_roles), chart_subjects resolve their chart's parent.

Implementation order: schema (1) → nav/tree (2) → routes/creation (3) → form (4) → reports (5) → seed/dev DB/e2e (6) → verification (7).
