## 2. New workflow `.github/workflows/deploy-backend.yml`
- Trigger: `workflow_dispatch` only (no auto-deploy on push), with a `no_cache` boolean input. Style follows `ci.yml` (name, permissions: contents: read).
- `concurrency: deploy-backend` (serialized, no cancel).
- Steps: checkout → write `secrets.PS_DEPLOY_SSH_KEY` to a key file (600) → write `secrets.PS_DEPLOY_HOST_KEY` to `known_hosts` (pinned host key, no runtime keyscan) → run `PS_DEPLOY_SERVER=${{ secrets.PS_DEPLOY_SERVER }} ./deploy-backend.sh` (+ `--no-cache` when the input is set). ubuntu-latest ships rsync and curl, so the script runs unmodified.

## 3. New `scripts/deploy-backend.mjs` + package.json script
Following `scripts/deploy.mjs` conventions (`execFileSync` helper, same voice):
- Refuse unless on `main`, and **block if `backend/` has uncommitted changes** — CI deploys committed code only, unlike today's rsync which ships uncommitted files; the script must say so explicitly.
- Push main if ahead of origin.
- Trigger via `gh workflow run deploy-backend.yml --ref main` (`-f no_cache=true` when invoked as `npm run deploy-backend -- --no-cache`); refuse a `--from-scratch` argument with a pointer to doing it over SSH.
- Grab the new run id and `gh run watch` it to completion, printing the run URL; helpful error with the Actions URL if `gh` is missing or unauthenticated.
- package.json: `"deploy-backend": "node scripts/deploy-backend.mjs"`.
